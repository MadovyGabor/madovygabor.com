# Gallery manifest validator: plan (phase 1, no code yet)

Branch: `feat/gallery-manifest-validator` (from `main`). Status: waiting for approval.

Scope of the tool: validate the photography gallery manifest `galleryData.json`
(generated by `utils/generate_gallery.py`, consumed by `javaScript/galleryLoader.js`).
No existing HTML, CSS, JS or Python file is changed by this work.

Path note: in this repo the photography site lives in `subdomains/photography/`.
All paths below that start with `utils/`, `javaScript/` or `galleryData.json` are
relative to `subdomains/photography/`.

Evidence notation: `gen:N` = `utils/generate_gallery.py` line N, `ldr:N` =
`javaScript/galleryLoader.js` line N, `json:N` = `galleryData.json` line N,
`doc:N` = `utils/instructions.md` line N. "Measured" means I ran a read-only
script over the committed `galleryData.json` (244 images, 28 sections).

## 1. Read-first findings

### 1.1 Top level

- The root is a JSON **array**, not an object (`gen:99` `gallery_data = []`, `gen:195`
  append, `gen:200` `json.dump(gallery_data, ...)`; `json:1` is `[`). It has **no
  top-level keys**. Measured: 5 elements.
- Encoding: UTF-8, `ensure_ascii=False`, `indent=4` (`gen:200`). Measured: no BOM.

### 1.2 Hierarchy and fields

| Level | Where created | Fields (measured on the committed file) |
|---|---|---|
| 1 category | `gen:147-151` | `title` string, `id` string, `subsections` array (5/5) |
| 2 section | `gen:165-169` or `gen:188-192` | `title`, `id` strings; **either** `subsections` array (4) **or** `images` array (9); never both (13/13) |
| 3 section | `gen:175-179` | `title`, `id` strings; `images` array (15/15); no `subsections` |
| image | `gen:63-68`, `gen:73-79` | see 1.3 |

- Folder layout the generator scans: `pictures/portfolio/<L1>/<L2>/[<L3>/]<image>`
  (`gen:26`, `gen:141-192`, `doc:8-36`). A level-2 folder that has subfolders is treated
  as a parent; its own loose images are ignored (`gen:160-162`, `doc:40`).
  Images directly inside a level-1 folder are never scanned (`gen:143`
  only descends into directories). Measured example:
  `pictures/portfolio/Rendezvények/csaladi-esemeny-unnep.webp` is tracked by git
  but is not in the manifest.
- Image extensions the generator accepts: `.jpg .jpeg .png .webp`, case-insensitive
  (`gen:92`). Measured: all 244 are `.webp`.
- Folders and files are sorted alphabetically (`gen:90`, `gen:141`, `gen:154`, `gen:171`).
  Sections with no images are omitted (`gen:174`, `gen:181`, `gen:187`, `gen:194`).

### 1.3 Image fields

| Field | Type (generator) | Format / value | Measured on the committed file |
|---|---|---|---|
| `src` | string | `img_path.relative_to(PHOTO_PAGE_DIR).as_posix()` (`gen:62`), so relative, forward slashes, starts with `pictures/portfolio/` (`gen:26`) | 244/244 strings; 0 duplicates; 0 backslashes; 0 leading slashes; 239 contain spaces and 225 contain non-ASCII characters (not URL-encoded); all 244 files exist on disk |
| `width` | integer | `Image.open(...).size[0]` (`gen:43`); **0 if the image could not be read** (`gen:40`, `gen:46-47`) | 244/244 int, all > 0 |
| `height` | integer | same as width | 244/244 int, all > 0 |
| `aspect_ratio` | float | `width / height` if `height > 0` (`gen:44-45`), else the default `1.5` (`gen:40`) | 244/244 float, all > 0, equal to width/height in all 244 (max difference 0.0); up to 16 decimals |
| `alt` | string, or localized object | always set by the generator (`gen:73`, `gen:75`, `gen:79`); fallback is derived from the filename and can be `""` if the cleaned stem is empty (`gen:58-60`); a localized object can come from `utils/image_metadata.json` or from the previous manifest (`gen:70-73`, `gen:120-128`) | 145 plain strings, 99 objects `{en, hu, sk}` with 3 non-empty strings each; 0 empty; 0 missing |
| `title` | string or localized object, **optional** | only set when the metadata entry has a truthy title (`gen:76-77`) | present on 99, always an object `{en, hu, sk}` with 3 non-empty strings; the 145 others have no `title` |

- Exactly these 6 keys appear on images (`src, width, height, aspect_ratio, alt, title`).
  No other image key was found.
- Section ids: `id = slugify(title)` (`gen:149`, `gen:167`, `gen:177`, `gen:190`; `gen:31-35`).
  Measured: true for all 28 sections. Sibling ids are unique (0 collisions).
  **Across the whole file one id is used twice:** `fesztival-hangulatkepek`
  (`json:392` under `koncertek/ava-night-26`, `json:1116` under
  `koncertek/hajomalom-fesztival-26`).

### 1.4 How the page consumes it

- Fetches `window.galleryDataPath || '../galleryData.json'` (`ldr:108`; set in `en/portfolio.html:324`, `hu/portfolio.html:325`) and prepends `window.galleryPathPrefix` (`'../'`, `en/portfolio.html:325`) to every `src` (`ldr:486`). So `src` must stay a relative path.
- Section `id` becomes a DOM id and a hash anchor (`ldr:326`, `ldr:350`, `ldr:423`, `ldr:435`) and is looked up with `document.getElementById` (`ldr:120-121`). A duplicate id gives an ambiguous anchor.
- If a level-2 section has `subsections`, the loader renders those and ignores its `images` (`ldr:419` branch vs `ldr:449-457`).
- The loader tolerates things the generator never writes: an image entry that is a bare string (`ldr:487`), a missing `alt` (falls back to the filename, `ldr:500-504`), `alt`/`title` as plain string or `{hu,sk,en}` object with fallback between languages (`ldr:494-496`, `ldr:508-512`), a missing `aspect_ratio` (defaults to 1.5, `ldr:489`), missing `width`/`height` (attributes just not set, `ldr:529`).

### 1.5 UNKNOWN (no rules will be invented for these)

- UNKNOWN: the full schema of `utils/image_metadata.json` (only its first entry was read: keyed by the `src` path, with `alt` as `{hu, sk, en}`). Not part of this plan unless you ask.
- UNKNOWN: whether the loader's translation table (`categoryTranslations`, `ldr:2-27`) is meant to cover every section `title`. No rule.
- UNKNOWN: whether bare-string image entries, missing `alt`, or non-`en/hu/sk` language keys are intended to be allowed. Only the loader code shows they work. See open questions.
- UNKNOWN: any minimum or maximum image size, file size, or title length. No rule.
- UNKNOWN: whether GitHub branch protection exists for `main` (not visible from the repo).

## 2. Proposed rules

Severity: **E** = error (exit code 1), **W** = warning (printed, exit code 0 unless `--strict`).
Every rule cites evidence from section 1. Rules marked (?) depend on an open question.

1. **Root is a non-empty array.** E. Evidence: `gen:99`, `gen:200`, `json:1`.
2. **Category object** has non-empty string `title`, non-empty string `id`, non-empty array `subsections`, and no `images`. E. Evidence: `gen:147-151`, `gen:194`, `ldr:323`.
3. **Section object** (levels 2 and 3) has non-empty string `title` and `id`, and **exactly one** of `images` / `subsections`, each a non-empty array. E. Evidence: `gen:165-179`, `gen:186-192` (never both), `gen:174`, `gen:187` (never empty), `ldr:419` (images ignored when `subsections` exist).
4. **Maximum depth is 3**: category, section, optional sub-section; level-3 sections hold only images. E. Evidence: `gen:141-192`, `ldr:416-457`.
5. **`id` equals `slugify(title)`**, using the same algorithm as `gen:31-35` (NFKD, drop non-ASCII, strip, lowercase, collapse spaces/hyphens). (?) Proposed E. Evidence: `gen:149,167,177,190`; holds for 28/28 sections.
6. **Sibling ids are unique.** E. Evidence: ids are DOM ids/anchors (`ldr:326,350,423,435`); 0 sibling collisions measured.
7. **Ids unique across the whole file.** (?) Proposed **W**, because the committed file already has one collision (`json:392`, `json:1116`); making it an error would fail the real file. Evidence: `ldr:120-121`.
8. **`src` is a non-empty string, relative, with forward slashes**: not starting with `/`, no `\`, no `..` segment, no URL scheme, and starting with `pictures/portfolio/`. Spaces and non-ASCII characters are allowed (not rejected). E. Evidence: `gen:26`, `gen:62`; `ldr:486` (prefix prepended); 239 paths with spaces measured.
9. **`src` extension is one of `.jpg .jpeg .png .webp`**, case-insensitive. (?) Proposed E with the generator's list. Evidence: `gen:92`.
10. **`src` values are unique across the whole file.** E. Evidence: each file is visited once (`gen:90-93`); 0 duplicates measured.
11. **`width` and `height` are integers greater than 0.** E. Evidence: `gen:43`; the failure value is `0` (`gen:40`, `gen:46-47`), which is exactly the broken state this rule catches.
12. **`aspect_ratio` is a finite number greater than 0.** E. Evidence: `gen:44-45`, `ldr:489`. Note: the generator's fallback `1.5` with `0` dimensions is already caught by rule 11.
13. **`aspect_ratio` matches `width / height`** within a tolerance. (?) Proposed W, off or on is your choice. Evidence: `gen:45`; max difference 0.0 on 244 images.
14. **`alt` is present and usable**: either a non-empty string, or an object with at least one non-empty string value. E. Evidence: `gen:73,75,79` (always set), `gen:58-60` (can be empty), `ldr:494-496`.
15. **Localized `alt`/`title` objects use only `en`, `hu`, `sk` as keys, with string values; all three present.** (?) Proposed: all-three-present is a W, any other key is a W, non-string value is an E. Evidence: 99/99 objects have exactly these three non-empty keys; the loader falls back between languages (`ldr:494-496`, `ldr:508-512`).
16. **`title` is optional**; if present it is a non-empty string or a localized object as in rule 15. E for wrong type. Evidence: `gen:76-77`, `ldr:508-512`.
17. **Unknown keys** on categories, sections and images. W. Evidence: only the keys listed in 1.2 and 1.3 are ever produced (`gen:63-77`, `gen:147-151`, `gen:165-169`, `gen:188-192`); measured on the committed file.
18. **Image entries must be objects** (bare strings rejected). (?) Proposed E. Evidence: generator only writes objects (`gen:63`); the loader tolerates strings (`ldr:487`), so this is a stricter choice. See open questions.
19. **File check (`--check-files`, off by default):** every `src` exists on disk relative to the photography site root. E when enabled. Evidence: `gen:62`; 244/244 exist.
20. **Orphan check (only with `--check-files`):** an image file under `pictures/portfolio/` that is not in the manifest. Proposed **info** only (never fails), because files directly in a category folder are ignored by design (`gen:143`; measured: `Rendezvények/csaladi-esemeny-unnep.webp`).
21. **Parsing:** the file must be valid UTF-8 JSON. Invalid JSON is a usage-level failure (exit code 2). No rule on indentation or line endings (the working tree has CRLF, `json:1` is `[` + CRLF).

## 3. Proposed file layout

All new, under `tools/manifest-validator/` unless noted. Nothing existing is edited.

```
tools/manifest-validator/
  package.json          "type": "module"; scripts build/test/validate; zero runtime dependencies
  package-lock.json     committed; CI uses `npm ci`
  tsconfig.json         strict, target ES2022, module NodeNext, outDir dist, rootDir .
  .gitignore            dist/ , node_modules/
  README.md             what it checks, how to run, exit codes, how to add a rule
  PLAN.md               this file
  src/types.ts          Manifest types + Issue { severity, rule, path, message }
  src/validate.ts       pure function validate(data: unknown, options): Issue[] (no I/O)
  src/cli.ts            reads the file, calls validate, prints issues, sets exit code
  test/validate.test.ts node:test unit tests (inline fixtures)
  test/cli.test.ts      node:test CLI tests (temp files, exit codes)
.github/workflows/gallery-manifest.yml    (repo root) runs build + test + validate
```

Run model: `tsc -p .` compiles to `dist/`; tests run with `node --test dist/test/`; the CLI is `node dist/src/cli.js [path]`.

Dependencies (all dev-only, none at runtime):

| Package | Version | Why |
|---|---|---|
| `typescript` | exact version pinned in phase 2 (no `^`) | compiler (`tsc`), the only build tool |
| `@types/node` | exact version pinned in phase 2, matching the Node major used in CI | types for `node:fs`, `node:path`, `node:test`, `node:assert` |

I could not look up current versions: the npm registry is not reachable from this sandbox (403 / name lookup failure), so I will not write unverified numbers. I will pin them in phase 2, taken from your machine's `npm view`. Observed locally for reference only: `tsc` reports `7.0.2` in the sandbox VM. No test framework, no JSON-schema library, no linter, no bundler. The workflow will use the GitHub-provided `actions/checkout` and `actions/setup-node` at pinned versions chosen in phase 2.

Default input path: see open question 2.

31. valid file: exit code 0, no output on stdout besides the summary
32. file with an error: exit code 1, the issue path is printed
33. file with only warnings: exit code 0; with `--strict`: exit code 1
34. missing file path or unreadable file: exit code 2
35. invalid JSON: exit code 2
36. `--check-files` with a missing image in a temp directory: exit code 1
37. `--check-files` with an orphan image: reported as info, exit code 0

## 5. Open questions (your decisions)

1. **Root shape.** The manifest root is an array with no top-level keys (`gen:99`). Your "missing top-level key" test becomes "category missing a required key" (test 5-7). OK?
2. **Default path.** The committed file is `subdomains/photography/galleryData.json`. Should running the CLI with no argument validate that file (resolved from the repo root, not from the current directory)? My suggestion: yes, with an optional path argument to override.
3. **Aspect ratio.** Validate only "finite number > 0" (rule 12), or also "equals width / height within a tolerance" (rule 13)? The committed file matches exactly. If yes: tolerance value, and warning or error?
4. **Duplicate id `fesztival-hangulatkepek`** exists in the committed file (`json:392`, `json:1116`), so a strict global-uniqueness rule would fail the real file. Options: (a) warning only (my proposal); (b) error, and you fix the data later; (c) skip global uniqueness. I will not edit `galleryData.json` or the generator.
5. **`id == slugify(title)`** (rule 5): error or warning? It holds for all 28 sections today, but a hand-edited id would break it.
6. **Localized `alt`/`title`.** Require all of `en`, `hu`, `sk`, or at least one? (I propose: at least one is an error condition, a missing language is a warning.)
7. **Leniency vs the loader.** The loader accepts bare-string images and a missing `alt` (`ldr:487`, fallback from the filename). Should the validator be stricter than the loader (my proposal: yes), or match it?
8. **Unknown keys:** warning (proposed), error, or ignore?
9. **Extensions:** accept all four the generator accepts (`gen:92`), or only `.webp` (all current files)?
10. **File checks:** keep `--check-files` off by default (proposed) or on? Orphan files such as `Rendezvények/csaladi-esemeny-unnep.webp` are info only, correct?
11. **Also validate `utils/image_metadata.json`?** Its schema beyond the first entry is UNKNOWN to me; I would not include it unless you say so.
12. **CI.** There is no `.github/` in the repo today. Run the workflow on pull requests only, or also on pushes? A push to `main` deploys on Cloudflare Pages independently, so this check can only block a merge if you enable branch protection with it as a required check (a GitHub setting, outside the repo). Also: which Node major should CI use?
13. **Output format:** human-readable text only (proposed), or also `--json`?
14. **Dependency versions** will be pinned in phase 2 from your machine (see section 3). OK, or do you prefer a different way?
